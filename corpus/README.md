# The corpus

100 documents, about 1,900 pages: the paperwork of a fictional bakery company,
Sunrise Bakery. It is built to make single-pass RAG fail in four specific ways
and to make those failures reproducible rather than anecdotal.

The subject is deliberately ordinary. Recipes, ovens, flour mills and three
bakery sites need no explaining, so the only thing left to think about is how
retrieval behaves.

Nothing here is generated by a model. The 29 documents that carry the facts
were written by hand; the rest come out of seeded Python.

## The story in one paragraph

Sunrise Bakery has three sites (High Street, Riverside, Station Road) and buys
flour from three mills (Alder, Birch Lane, Cedar Valley). Its Classic
Sourdough, product code SD-12, changed flour in 2024, was withdrawn from sale
in 2025, and had its baking procedure revised later that year. A near-twin,
the Country Sourdough (SD-13), shares almost every word with it and differs in
the numbers that matter. Around those few documents sit dozens of logs,
registers and checklists that look relevant and are not.

## What is where

| Path | What it is | Edit? |
|---|---|---|
| `manifest.yaml` | The fact table — entities, negatives, the 17 questions | **Yes, this is the source of truth** |
| `document-spec.yaml` | For each hand-written document: strings it must and must not hold | Yes |
| `source/*.md` | Document text (98 files: 29 hand-written + 2 specification books + 18 constrained + 49 ballast) | Hand-written yes; generated no |
| `documents/*.pdf` | Rendered and committed. **The only directory that gets ingested** | Never — regenerate |
| `sections/*.json` | Ground-truth section and page ranges, written by the renderer | Never — output |
| `generate/` | Seeded generators + ingest | Yes |
| `render/render.py` | Markdown → PDF + sidecar | Yes |
| `tests/` | The verification suite | Yes |

**Never ingest anything but `documents/`.** The manifest holds every expected
answer; putting it in the collection would leak them into retrieval.

## The four tiers

| Tier | Count | What it is |
|---|---|---|
| Authored | 31 | Carry the facts the questions depend on |
| Constrained | 18 | 12 monthly waste returns and 6 routine recipe changes, seeded so the counting questions have known answers |
| Special | 2 | A scanned certificate with no text layer, and a diagram that is only callouts |
| Ballast | 49 | Fridge logs, delivery manifests, training records: filler that buries the right passage |

## The workflow

```bash
# 1. change manifest.yaml and/or a file in source/
# 2. check the source before spending anything on rendering
.venv/bin/python corpus/tests/check_source.py      # hand-written: verbatims, must-not-hold
.venv/bin/python corpus/tests/check_ballast.py     # ballast: closed vocabulary

# 3. regenerate whatever is machine-made
.venv/bin/python corpus/generate/constrained.py    # 12 waste returns + 6 recipe changes, asserts ag-01/02/03
.venv/bin/python corpus/generate/specbooks.py      # the two Product Specification Books
.venv/bin/python corpus/generate/ballast.py        # 49 filler documents
.venv/bin/python corpus/generate/special.py        # 2 PDF-native parsing challenges
.venv/bin/python corpus/generate/eval_suites.py    # evaluations/*.json from the manifest

# 4. render (a filename argument renders just that one)
.venv/bin/python corpus/render/render.py
.venv/bin/python corpus/render/render.py RC-88_flour_change.md

# 5. verify against EXTRACTED PDF TEXT — this is the one that counts
.venv/bin/python corpus/tests/verify_corpus.py

# 6. load it
.venv/bin/python corpus/generate/ingest.py --fresh
```

### Why step 5 is not optional

`check_source.py` reads Markdown. Extraction rewraps lines, reorders table
cells, and puts page headers and footers into every page's text — so the
chunk-boundary assertions are only true or false **after rendering**.
`verify_corpus.py` runs the real extractor (`backend/app/extractors.py`) and
a fixed 1000-character splitter with 180 overlap, and checks 44 constraints,
including:

- no document holds `SD-12` and `High Street` together → mh-01 stays several lookups
- a chunk holds `230 °C` with no `deck oven` → the context-loss example
- the baked-weight row is cut off from its column headers
- the Level 3 rule is stranded from the sentence that limits its scope
- `Market Square` and `calories` appear nowhere, ballast included

A **passing** multi-hop row in the benchmark means the corpus is not hard
enough.

## Two rules that are easy to break by accident

**Page ranges are never authored.** The renderer writes `sections/*.json` from
the actual layout. Ingestion does *not* read the sidecar — it detects headings
the way it would on any document, so the sidecar is ground truth for tests
rather than a shortcut past them.

**`evaluations/*.json` is generated.** It comes from `manifest.yaml` via
`generate/eval_suites.py`. Edit the manifest and regenerate; hand edits are
lost on the next run.

## Known, deliberate

- `inspection_cert_scanned.pdf` **fails ingestion.** It is image-only and
  `_extract_pdf` raises on it. 99 of 100 is a clean run.
- Only four documents carry a status header, and all four are superseded: the
  2024 specification book, the 2024 approval matrix, revision C of the baking
  instruction and the old catalogue. Normal searches leave them out.
- Ambiguous questions need `OPENROUTER_API_KEY`, or they fail for the wrong
  reason — `detect_ambiguity` returns early without it.
- `ag-01` needs 12 sources and `/evaluations/run` uses `limit=8`, so it fails
  on arithmetic. Correct outcome, but not evidence about the corpus.
