# The corpus

100 documents, ~1,930 pages, built to make single-pass RAG fail in four
specific ways and to make those failures reproducible rather than anecdotal.

Nothing here is generated by a model at build time. The 31 documents that
carry facts were written by hand; the other 69 come out of seeded Python.

## What is where

| Path | What it is | Edit? |
|---|---|---|
| `manifest.yaml` | The fact table — entities, negatives, the 25 questions | **Yes, this is the source of truth** |
| `document-spec.yaml` | One brief per document: length, sections, holds, must-not-hold | Yes |
| `source/*.md` | Authored content (98 files: 31 authored + 18 constrained + 49 ballast) | Authored yes; generated no |
| `documents/*.pdf` | Rendered, frozen, committed. **The only directory that gets ingested** | Never — regenerate |
| `sections/*.json` | Ground-truth section→page ranges, written by the renderer | Never — output |
| `generate/` | Seeded generators + ingest | Yes |
| `render/render.py` | Markdown → PDF + sidecar | Yes |
| `tests/` | The verification suite | Yes |

**Never ingest anything but `documents/`.** The manifest holds every expected
answer; putting it in the collection would leak them into retrieval.

## Authority

`manifest.yaml` is the source of truth. Never adjust the corpus to protect a
number that was guessed before measuring. Measure, then record the result.

## The workflow

```bash
# 1. change manifest.yaml and/or a file in source/
# 2. check the source before spending anything on rendering
.venv/bin/python corpus/tests/check_source.py      # authored: verbatims, must-not-hold
.venv/bin/python corpus/tests/check_ballast.py     # ballast: closed vocabulary

# 3. regenerate whatever is machine-made
.venv/bin/python corpus/generate/constrained.py    # 12 rework + 6 CRs, asserts ag-01/02/03
.venv/bin/python corpus/generate/ballast.py        # 49 filler documents
.venv/bin/python corpus/generate/special.py        # 2 PDF-native parsing challenges
.venv/bin/python corpus/generate/eval_suites.py    # evaluations/*.json from the manifest

# 4. render (a filename argument renders just that one)
.venv/bin/python corpus/render/render.py
.venv/bin/python corpus/render/render.py CR-88_seal_material.md

# 5. verify against EXTRACTED PDF TEXT — this is the one that counts
.venv/bin/python corpus/tests/verify_corpus.py

# 6. load it
.venv/bin/python corpus/generate/ingest.py
```

### Why step 5 is not optional

`check_source.py` reads Markdown. Extraction rewraps lines, reorders
multi-column tables, and puts page furniture into every page's text — so the
chunk-boundary assertions are only true or false **after rendering**.
`verify_corpus.py` runs the real extractor (`backend/app/extractors.py`) and
the real splitter (1000/180) and checks 36 constraints, including:

- no chunk holds `BV-12` + `Bamberg` → mh-01 stays three hops
- a chunk holds `40 Nm` with no `M8` → the context-loss example
- the flatness row is orphaned from its column header
- the Level 3 rule is stranded from its safety-critical scope
- `Regensburg` and `warranty` appear nowhere, ballast included

A **passing** multi-hop row in the benchmark means the corpus is not hard
enough.

## Two rules that are easy to break by accident

**Page ranges are never authored.** The renderer writes `sections/*.json` from
the actual layout. Ingestion does *not* read the sidecar — it detects headings
the way it would on a real corpus, so the sidecar is ground truth for tests
rather than a shortcut past them. If a spec page count disagrees with a
sidecar, the sidecar is right.

**`evaluations/*.json` is generated.** It comes from `manifest.yaml` via
`generate/eval_suites.py`. Edit the manifest and regenerate; hand edits are
lost on the next run.

## Known, deliberate

- `inspection_cert_scanned.pdf` **fails ingestion.** It is image-only and
  `_extract_pdf` raises on it. 99 of 100 is a clean run.
- `extractors.py` returns `section: None` for every PDF page. Section
  detection is not built; the sidecars already hold the answer.
- Ambiguous questions need `OPENROUTER_API_KEY`, or they fail for the wrong
  reason — `detect_ambiguity` returns early without it.
- `ag-01` needs 12 sources and `/evaluations/run` uses `limit=8`, so it fails
  on arithmetic. Correct outcome, but not evidence about the corpus.
